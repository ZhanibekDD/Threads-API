# Что дальше — по шагам

## Инфраструктура: решение по этапам

**Этап 1 (сейчас):** всё работает с вашего компьютера — Docker Compose
(`docker-compose.yml`) поднимает панель, фоновый поиск и Cloudflare quick
tunnel для публичного HTTPS-адреса. Адрес туннеля **временный** и меняется
при каждом перезапуске контейнера `cloudflared` (перезагрузка ПК, перезапуск
Docker Desktop, сбой контейнера) — тогда придётся заново вписать новый адрес
в три поля App Dashboard (раздел ниже) и в `THREADS_REDIRECT_URI` в `.env`.
Это сознательно принятое ограничение, не забытая недоделка.

**Этап 2 (потом, не сейчас):** перенос на нормальный хостинг с постоянным
доменом (например, поддомен `zakonexpertt.kz`) — тогда адрес перестанет
меняться, и все три поля в App Dashboard настраиваются один раз навсегда.
Когда будете готовы — скажите, помогу с деплоем и настройкой домена.

### Экран «Вход через Facebook для компаний» — что вписать в поля

Этот экран отдельно от «Доступ к Threads API», но тоже входит в чек-лист
готовности приложения. Три поля и что с ними делать:

| Поле | Что вписать | Работает ли с локального компьютера |
|---|---|---|
| **Действительные URI перенаправления для OAuth** | `http://127.0.0.1:5000/threads/callback` (или ваш публичный адрес, если уже есть) | Да — это редирект **браузера пользователя**, локальный адрес подходит для тестирования |
| **Деавторизация URL обратного вызова** | `http://<ваш-публичный-адрес>/threads/deauthorize` | **Нет** — Meta стучится на этот URL сама, с сервера на сервер, `127.0.0.1` не видна снаружи |
| **URL запроса на удаление данных** | `http://<ваш-публичный-адрес>/threads/data-deletion` | **Нет**, по той же причине |

Оба вебхука уже реализованы и протестированы в коде
([`app/web.py`](../app/web.py): `threads_deauthorize()`,
`threads_data_deletion()`, `threads_data_deletion_status()`) — они проверяют
криптографическую подпись Meta (`signed_request`, HMAC-SHA256 с
`THREADS_APP_SECRET`) и очищают сохранённый токен.

**Проблема:** последние два поля физически не могут работать с `127.0.0.1` —
Meta должна дотянуться до них сама через интернет, а localhost снаружи не
виден. Варианты:

1. **Временный публичный туннель, компьютер остаётся ваш** — например
   `ngrok http 5000` (бесплатный тариф подходит). Получите адрес вида
   `https://abcd1234.ngrok-free.app`, впишите в оба поля
   `.../threads/deauthorize` и `.../threads/data-deletion`, а также обновите
   `THREADS_REDIRECT_URI` на `.../threads/callback`. Работает, пока запущен
   `ngrok` и панель — ничего никуда не разворачивается «навсегда».
2. **Оставить эти два поля пустыми** и проверить, сохраняется ли форма и
   пропускает ли это дальше по чек-листу — иногда Meta допускает вместо
   отдельного callback-URL просто ссылку на страницу с инструкцией
   («Data Deletion Instructions URL» в **Основных настройках** приложения,
   не на этом экране) — туда можно подставить будущий
   `https://zakonexpertt.kz/data-deletion` после публикации той страницы
   (раздел 2 ниже).
3. Отложить эти два поля до момента, когда решите деплоить панель на
   постоянный сервер — тогда впишите реальный домен.

Я не запускал `ngrok` и не менял ничего в этом сценарии сам — решать, какой
вариант подходит, вам.

## 3. Локальный автозапуск (Этап 1 — сделано вместо деплоя на сервер)

Всё работает в Docker (`docker-compose.yml`): панель, фоновый поиск и
Cloudflare-туннель — три контейнера с `restart: unless-stopped`, то есть
сами поднимаются заново при сбое или перезапуске Docker.

Единственное, что нужно включить вручную (я не могу менять автозагрузку
системы без вашего отдельного подтверждения) — чтобы **сам Docker Desktop**
запускался при входе в Windows:
Docker Desktop → Settings → General → **«Start Docker Desktop when you sign
in»**.

Полезные команды (из папки проекта):
```
docker compose ps           # статус контейнеров
docker compose logs -f      # логи всех сервисов
docker compose restart web  # перезапустить только панель
docker compose down         # остановить всё
docker compose up -d        # запустить всё заново
```

**После любого перезапуска `cloudflared`** адрес туннеля меняется — новый
адрес смотрите так:
```
docker compose logs cloudflared | grep trycloudflare.com
```
и обновляете его в трёх полях App Dashboard + `THREADS_REDIRECT_URI` в `.env`
(после чего `docker compose up -d --force-recreate web search-loop`, чтобы
подхватить новое значение).
